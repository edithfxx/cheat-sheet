# 我怎麼與 AI 協作開發

本專案自 2026-05-26 起，全程以 Claude Code 開發。

這份文件的重點**不是「我用了 AI」**，而是四件事：我怎麼讓 AI 產出我要的東西、怎麼讓它先規劃再動手、怎麼驗收它的產出，以及**哪些建議我否決了**。

---

## 1. 怎麼叫 AI 寫出我要的東西：先寫規格，再讓它動手

專案第一天就建立了 [`CLAUDE.md`](../CLAUDE.md) —— 一份專案脈絡文件，內容包含技術棧與選用理由、卡片資料 schema、UI 設計規格、關鍵設計決策，以及**明確的禁止事項**。每次新對話開始，AI 先讀這份文件再動手。

這解決了 AI 協作最常見的失敗模式：每次對話都要重新解釋專案背景，且 AI 每次給出不同方向的建議。

最有效的是「禁止事項」段落。例如 `CLAUDE.md` 第 2 節直接寫死：

> **重要：不要建議改用 React / Vite / Next.js / TypeScript。** 這些都討論過並被刻意排除。

沒有這句話時，AI 幾乎每次都會建議「要不要考慮導入 Vite」。寫進規格之後就再也沒出現過。

**把已經做過的決策寫下來，比每次重新爭論有效率。**

---

## 2. 怎麼叫 AI 規劃：讓它把待決事項列成清單，我逐條拍板

專案啟動時我的需求只有一句話：「想建立一個速查表，可快速閱覽、可搜尋、可快速複製、可編輯」，附一份手邊的 PDF 筆記。

我沒有讓 AI 直接開始寫。而是要求它把從這句話到可執行規格之間的待決事項，整理成編號清單讓我逐條決定：

| 決策 | 選項 | 我的決定 |
|---|---|---|
| 「CSS 應用題」獨立成主分類還是併入 CSS | 獨立 / 併入 | **獨立** —— 實戰問題集與屬性說明調性不同 |
| 「未完成 / 研究中」項目是否收錄 | 收 / 不收 | **不收** —— 速查表只放已驗證可用的東西 |
| 純觀念說明（非程式碼）是否收錄 | 收 / 不收 | **收** —— 催生了 `note` 型別 |
| 60 行的 Vue 初始架構怎麼存 | 整段一張卡 / 拆多區塊 | 拆區塊 —— 催生了 `sections` 型別 |

**5 種卡片型別不是一開始就設計好的，是從這些取捨長出來的。**「觀念說明要不要收」直接催生了沒有複製按鈕的 `note` 型別；「超長範本怎麼存」催生了可摺疊的 `sections` 型別。

規格沒對齊之前不寫任何一行 code —— 這一步省下的返工，比任何 code 生成速度都值錢。

## 3. 怎麼判斷 AI 給的是我要的

**讓不確定性可見。** `CLAUDE.md` 第 9 節定義了協作規則：

- **不會就直說「不會」**，不要編答案
- **生成檔案前要先問**，不要主動產出大檔案
- **不要過度道歉、不要過度肯定**，老實話為主

AI 最危險的不是答錯，而是用同樣自信的語氣講對的事和錯的事。這些規則就是為了逼出區別。

**驗證上用最低成本的方法。** 本專案刻意不引入測試框架（見 [`DECISIONS.md`](DECISIONS.md) 決策 1），改為每次 AI 修改後跑一次語法檢查：

```bash
node --check script/app.js
node --check script/config.js
```

通過才進瀏覽器測試。在無建置流程的專案裡，這是攔截低級錯誤成本最低的方式。

## 4. 我否決或修正了什麼

這一節是重點。以下每一項的完整理由與代價分析，見 [`DECISIONS.md`](DECISIONS.md)。

| AI 的提案 | 我的決定 | 判斷依據 |
|---|---|---|
| 多層資料來源 fallback：`update/` 找不到就退回 `default/` 種子資料 | **否決**，收斂為單一檔案、找不到就報錯 | 加上 localStorage 會變成三層來源，出問題時無法判斷「現在看到的是哪一份」。單人工具的可預測性 > 容錯（決策 5）|
| 匯出檔名帶時間戳，使用者下載後手動改名 | **要求移除**，檔名固定 `data.json` | 那個改名步驟是多餘摩擦。AI 同時補上我沒想到的邊界情況：瀏覽器遇同名檔會存成 `data (1).json` |
| 左側 sidebar 放子分類 | **改為右下角浮動按鈕開 Modal** | sidebar 讓卡片區只剩 3 欄，把橫向空間讓出來才能做到桌面 4 欄 |
| regex 自製語法高亮壞掉，建議修 regex 或改用 Prism.js | **選第三條路：整個移除** | 回到產品目的 —— 速查表的核心價值是準確複製，不是好看。顯示錯誤比沒有顏色嚴重（決策 9）|

### 一次 AI 反過來質疑我，而它是對的

改成浮動按鈕時，我提供的參考圖示是「上箭頭 + 底線」（go-top 的圖示）。AI 指出這個按鈕的功能是「開啟子分類選單」，圖示語意對不上，並提出替代方案。

這個質疑是對的，最後採用了語意相符的圖示。

**AI 不該只是照做。設定成會反駁的協作模式，比設定成順從的更有價值** —— 這也是第 3 節那些協作規則要達成的效果。
